Smart search performance lab

Deliverable (b): the same fuzzy-matching search run two ways, so the before/after difference in UI responsiveness is visible rather than just described. Type a query above first, then run each mode below and watch the spinners.

Before — main thread (blocking)

Runs the match-scoring algorithm directly on the UI thread, the way a naive implementation would. On a slow device this is what freezes scrolling and taps.

After — Web Worker (async)

Same algorithm, offloaded to a background thread (Web Worker — the browser equivalent of an Android Service/AsyncTask/Kotlin coroutine off the main thread). The spinner keeps spinning smoothly throughout.
